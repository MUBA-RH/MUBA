- incident count
- learning queue count

This turns Founder status into an operational observability interface,
not just a decorative command.

34.10 MULTI-INTENT ARBITRATION EXISTS

The Master Brain includes a multi-intent detection path.

The intended behavior is:
one message may contain several independent requests and should be
arbitrated as a combined context rather than handled by the first keyword
that matches.

34.11 SECURITY EVIDENCE IS STRUCTURED

The security model records/uses:

- target user ID
- message ID
- chat ID
- context
- source
- independent evidence when available
- confidence
- prior incident history

Moderation decisions should verify target, message, context, evidence,
risk, and permissions before action.

34.12 ROSE IS AN EXECUTION BOUNDARY

MUBA remains the decision/analysis center.

ROSE is an execution helper when moderation action is required.

The handoff is intentionally minimal:

incident ID
target user ID
action
category
risk

A bot's displayed name/profile is not authority proof.

34.13 MEDIA IS EVIDENCE, NOT AUTHORITY

Media intelligence can cover:

- text
- images
- audio
- files
- links

Possible extraction:
OCR
transcription
file inspection
link inspection

But extracted media content is evidence, not truth, and file/OCR contents
must never be interpreted as privileged system commands.

34.14 AUTHORIZATION IS CHAT-ID BASED

Full MUBA behavior belongs only in Founder-authorized groups.

Unauthorized groups do not receive normal:
- chat
- learning
- memory
- web
- moderation

Group authorization uses real Chat ID.

If an official group Chat ID changes, the old state is archived and the
new ID requires confirmation.

34.15 ACTION RESULT VERIFICATION

The action engine distinguishes:
"request sent"
from
"action completed".

This is one of the most important reliability findings.

The system should verify the actual result wherever possible instead of
assuming a successful API call equals a successful business action.

34.16 PRIVACY WALLS

The architecture explicitly separates user/group memory.

User-specific information must not leak into another user's context.
Group-specific context must remain scoped to that group.

This is essential because the brain is designed to retain long-term
context.

34.17 CHARACTER EVOLUTION HAS A FIREWALL

Dynamic:
- slang
- memes
- humor
- community culture
- conversational habits

Protected:
- core MUBA identity
- core philosophy
- official knowledge
- Founder authority
- permanent security boundaries

Major character changes should surface to Founder.

34.18 AUTONOMY HAS BOUNDARIES

MUBA is intended to operate autonomously inside protected boundaries.

Autonomy does not mean:
- changing official truth silently
- changing Founder authority
- rewriting permanent security rules
- turning every learned pattern into identity

The correct model is:
autonomous operation + protected domains + escalation when boundaries
are reached.

34.19 DEVELOPMENT SEPARATION

DEV/internal controls are intended to remain separate from public
conversation behavior.

This prevents internal maintenance/debugging concepts from becoming
ordinary public-chat commands.

34.20 UNIFIED BRAIN IS THE FINAL SYNTHESIS

34.22 MOST IMPORTANT 800+ FINDING

The strongest finding after the 800+ investigation is not a single new
feature.

It is that the later design converges on a coherent operating model:

OBSERVE
-> UNDERSTAND

-> ACT WHEN AUTHORIZED

34.23 HISTORICAL DATA INTEGRITY RULE

The database/search pass found repeated copies of the Deep Master Note,

It did NOT reveal a complete raw transcript containing every numbered
decision after 800.

Therefore:

- recovered design principles are recorded as design principles
- missing numbered historical messages are NOT fabricated
- duplicate files are not treated as independent decisions

34.24 FINAL 800+ PRINCIPLE

The later MUBA architecture is not primarily about making MUBA talk more.

It is about making MUBA:
- understand before answering
- remember without leaking
- learn without blindly trusting
- verify before treating information as official
- distinguish plans from facts
- distinguish authority from usernames
- distinguish evidence from truth
- distinguish requested actions from completed actions
- remain quiet when nothing requires intervention
- become active when context, security, support, or importance requires it

The visible character remains MUBA.

The internal system carries the complexity.
